PROJECT REPORT // SLIME PROJECT

상태머신 기반 게임 로직 및 확장 가능한 몬스터 AI 시스템

UnityAIFSMDesign Pattern

Slime Project는 하드코어 액션 퍼즐 플랫포머 게임으로, FiniteStateMachine(FSM) 기반 상태 관리 시스템을 통해 모든 게임 엔티티의 행동을 체계적으로 관리합니다. 플레이어 슬라임의 움직임, 변신 능력, 그리고 변신 시 능력 변화를 구현했으며, 보스 몬스터와 일반 몬스터의 AI 로직을 담당하여 확장 가능한 게임 시스템을 구축했습니다.

2. FiniteStateMachine 기반 상태 관리 시스템

몬스터와 플레이어의 상태 클래스가 공통 State를 상속하도록 구성했습니다. Enter / Exit / LogicUpdate / PhysicsUpdate / DoChecks 호출 규약을 공유하고, 몬스터는 Monster_State, 플레이어는 Player_State에서 각 대상에 필요한 참조와 동작을 확장합니다. 공통 기반 클래스를 공유하되 상태 인스턴스는 각 객체가 따로 관리합니다.

몬스터는 FiniteStateMachine이 현재 상태의 전환과 업데이트를 관리합니다. 플레이어는 이동·공격·대시·사망 기능 객체를 조합하고 Player_Slime이 조건에 따라 직접 호출하여 기존 조작 방식을 유지합니다.

2.1 상태머신 구조 및 전환 플로우

몬스터가 사용하는 FiniteStateMachine은 공통 State 타입으로 현재 상태를 보관합니다. 상태 전환 시 이전 상태의 Exit를 호출한 뒤 새 상태의 Enter를 호출합니다. 아래 전환 흐름은 몬스터 FSM에 해당하며, 플레이어 기능 객체의 호출은 Player_Slime이 담당합니다.

TRIGGER Initial State Setup (최초 상태 설정)

1. State::Enter (상태 진입 및 초기화)

INIT

몬스터 분기에서 애니메이션 bool 활성화와 시작 시간 기록, 행동 상태별 속도·플래그 초기화

2. Execution Loop (프레임 업데이트)

LOOP

LogicUpdate(): AI 로직 연산  |  PhysicsUpdate(): 물리 이동 및 충돌 판정

판단

Trigger Transition? (전환 조건 충족 여부)

No
현재 상태 유지 (Execution Loop 지속)
Yes
ChangeState() 호출 → 상태 전환 착수

3. State::Exit & NewState::Enter (순차 전환)

TRANSACTION

이전 상태의 Exit() 호출 후 새 상태의 Enter() 호출로 종료와 진입 순서 유지

STABLE 몬스터 FSM의 상태 종료·진입 순서 일관성 유지

상태머신 핵심 로직 몬스터 상태머신의 초기화와 Exit → Enter 호출 순서를 구현한 실제 코드입니다.

코드 보기: FiniteStateMachine.cs 
using System.Collections;
using System.Collections.Generic;
using UnityEngine;

// 적들의 상태를 추적하고, 상태에 따른 올바른 코드를 실행시킨다
public class FiniteStateMachine
{
    public State currentState { get; private set; }

    public void Init(State startingState) // 유한상태머신을 초기화한다는 의미
    {
        currentState = startingState;     // 현재 상태 설정
        currentState.Enter();             // 그 상태를 실행
    }

    public void ChangeState(State newState) // 상태 변경
    {
        currentState.Exit();                // 전의 상태를 종료하고
        currentState = newState;            // 현재 상태를 업데이트
        currentState.Enter();               // 현재 상태에 돌입
    }
}

2.2 State 베이스 클래스

State는 특정 엔티티나 애니메이션 파라미터에 의존하지 않는 공통 기반 클래스입니다. 기본 메서드는 부수 효과 없이 비어 있으며, 각 하위 클래스가 필요한 동작을 재정의합니다. 몬스터의 애니메이션 제어·시작 시간 기록·센서 검사는 Monster_State에서 처리합니다.

State
├── Monster_State
│   ├── MoveState
│   ├── JumpState
│   └── Dash / AttackState 등
└── Player_State
    ├── Player_Movement
    ├── Player_Attack
    ├── Player_Dash
    └── Player_Dead
코드 보기: State.cs 
// Shared lifecycle for monster states and player feature modules.
// Owner-specific data and side effects belong to the specialized branches.
public class State
{
    public virtual void Enter() { }
    public virtual void Exit() { }
    public virtual void LogicUpdate() { }
    public virtual void PhysicsUpdate() { }
    public virtual void DoChecks() { }
}

몬스터 공통 처리와 행동 확장

일반 몬스터의 행동 상태는 State → Monster_State → 공통 행동 상태 → 몬스터별 상태 순서로 확장합니다. Monster_State는 몬스터 엔티티와 FSM 참조를 보관하고, 진입 시 시작 시간 기록·애니메이션 활성화·센서 검사를 처리합니다. 플레이어의 Player_State와 같은 State를 공유하면서 몬스터에 필요한 동작을 별도로 유지합니다.

  • Bear (돌진형): Bear_DashState : DashState로 돌진을 구현하고, 돌진 종료 후 플레이어 감지 여부에 따라 감지·탐색 상태로 전환합니다.
  • Spider (도약형): Spider_JumpState : JumpState로 공중 이동을 처리하고, 착지 후 감지·이동 상태로 전환합니다.
  • Ant (기본형): Ant_MoveState로 순찰·방향 전환을 처리하고, Ant_MeleeAttackState에서 공격 범위를 판정해 피해를 적용합니다.
코드 보기: Monster_State.cs - 몬스터 공통 기반 
using System.Collections;
using System.Collections.Generic;
using UnityEngine;

// 적들의 상태가 가져야 하는 모든 기능을 포함하는 상태 클래스, 여러 상태들은 이 state클래스를 상속받음
// 적 클래스에서 해당 상태의 객체를 생성하고 유한상태 머신을 이용하여 우리가 어떤 상태인지를 추적한다.
public class Monster_State : State
{
    protected FiniteStateMachine stateMachine;  // 상태머신
    protected Monster_Entity entity;                    // 객체 (몬스터의 부모 객체)

    protected float startTime;                  // 상태 시작 시간.

    protected string animBoolName;              // 애니메이션에 따른 파라미터 이름

    public Monster_State(FiniteStateMachine stateMachine, Monster_Entity entity, string animBoolName)
    {
        this.stateMachine = stateMachine;
        this.entity = entity;
        this.animBoolName = animBoolName;
    }

    public override void Enter()                     // 어떤 상태에 돌입했을 시,
    {
        startTime = Time.time;                      // 스타트 시간을 현재시간으로 설정
        entity.anim.SetBool(animBoolName, true);    // 파라미터세팅
        DoChecks();                                 // 체크해야될 요소 확인

        Debug.Log("Enter: " +  animBoolName);
    }
    public override void Exit()
    {
        entity.anim.SetBool(animBoolName, false);   // 애니메이션 종료
    }
    public override void LogicUpdate()
    {

    }
    public override void PhysicsUpdate()
    {
        DoChecks();
    }

    public override void DoChecks()          // 주기적으로 체크하기 위해 존재하는 함수
    {

    }

}

곰의 돌진 상태는 DashState → Dash → Monster_State → State 상속 경로를 사용합니다. 아래 실제 코드에서 공통 돌진 로직을 호출하고, 곰 전용 상태 전환과 물리 저항값을 추가합니다.

코드 보기: Bear_DashState.cs - 몬스터별 확장 
using System.Collections;
using System.Collections.Generic;
using UnityEngine;

public class Bear_DashState : DashState
{
    private BearMonster bear;
    public Bear_DashState(FiniteStateMachine stateMachine, Monster_Entity entity, string animBoolName, D_DashState stateData, BearMonster bear) : base(stateMachine, entity, animBoolName, stateData)
    {
        this.bear = bear;
    }

    public override void DoChecks()
    {
        base.DoChecks();
    }

    public override void Enter()
    {
        base.Enter();
        bear.atsm.dashState = this;
    }

    public override void Exit()
    {
        base.Exit();
    }

    public override void LogicUpdate()
    {
        base.LogicUpdate();

        if (isAnimatioonFinished && !performDashAction)
        {
            entity.rb.drag = 0;
            if (isPlayerInMinAgroRange)    // 플레이어가 존재한다면
            {
                stateMachine.ChangeState(bear.playerDetectedState); // 플레이어가 감지되었는가?
            }
            else
            {
                stateMachine.ChangeState(bear.lookForPlayerState);  // 플레이어 탐색
            }
        }
    }

    public override void PhysicsUpdate()
    {
        base.PhysicsUpdate();
    }

    public override void TriggerDashing()
    {
        base.TriggerDashing();
        entity.rb.drag = stateData.dashDragValue;
    }
    public override void FinishDashing()
    {
        base.FinishDashing();
    }
}

2.3 초기화부터 상태 전환까지의 실행 흐름

곰 몬스터의 실제 실행 경로를 따라가면, 상태 객체를 만드는 시점과 현재 상태를 실행하는 주체를 구분할 수 있습니다.

  1. 상태머신 생성: BearMonster.Start()가 base.Start()를 호출합니다. Monster_Entity.Start()에서 FiniteStateMachine을 만들고 물리·애니메이션·이벤트 전달용 참조를 연결합니다.
  2. 상태 객체 생성과 최초 진입: 곰은 이동·대기·감지·돌진·탐색·점프·기절·사망 상태 객체를 한 번씩 생성합니다. 실제 시작 호출은 stateMachine.Init(moveState)이며, 이동 상태의 Enter()에서 이동 속도와 이동 시간을 설정합니다.
  3. 논리·물리 호출 분리: Monster_Entity.Update()는 currentState.LogicUpdate()를, FixedUpdate()는 currentState.PhysicsUpdate()를 호출합니다. Monster_State.PhysicsUpdate()는 DoChecks()로 감지값을 갱신합니다. 두 루프의 호출 횟수가 항상 일대일인 것은 아닙니다.
  4. 조건 판단과 상태 교체: Bear_MoveState.LogicUpdate()는 base.LogicUpdate()로 이동 시간 만료를 먼저 계산한 뒤 감지값과 타이머를 확인합니다. 조건이 맞으면 ChangeState()가 이전 상태 종료 → 현재 참조 교체 → 새 상태 진입 순서로 실행됩니다.

상태 전환마다 객체를 다시 생성하지 않고 이미 만들어 둔 상태를 재사용합니다. 따라서 Enter()에서 타이머와 동작 플래그를 초기화하는 것이 중요합니다. 이 구현의 Init()과 ChangeState()에는 null 검사가 없으므로, 상태 객체와 엔티티 참조를 모두 준비한 뒤 최초 진입과 전환을 호출합니다.

코드 보기: BearMonster.cs - 상태 생성과 최초 진입 
// BearMonster.cs의 Start() 발췌
public override void Start()
{
    base.Start();

    idleState = new Bear_IdleState(stateMachine, this, "idle", idleStateData, this);      // Idle상태를 추가
    moveState = new Bear_MoveState(stateMachine, this, "move", moveStateData, this);      // Move상태를 추가
    playerDetectedState = new Bear_PlayerDetectedState(stateMachine, this, "playerDetected", playerDetectedStateData, this);
    dashState = new Bear_DashState(stateMachine, this, "dash", dashStateData, this);
    lookForPlayerState = new Bear_LookForPlayerState(stateMachine, this, "lookForPlayer", lookForPlayerStateData, this);
    jumpState = new Bear_JumpState(stateMachine, this, "jump", jumpStateData, this);
    stunState = new Bear_StunState(stateMachine, this, "stun", stunStateData, this);
    deadState = new Bear_DeadState(stateMachine, this, "dead", deadStateData, this);

    stateMachine.Init(moveState);       // Entity에 존재하는 상태머신을 움직임 상태로 초기화시킴
}

감지값 갱신과 전환 판단의 분리

MoveState.DoChecks()는 플레이어·벽·절벽·접지·점프 필요 여부를 읽어 필드에 저장합니다. 이 검사는 상태 진입 시와 물리 업데이트 시 수행되고, 곰의 논리 업데이트는 가장 최근에 저장된 값을 사용해 다음 동작을 결정합니다.

코드 보기: MoveState.cs - 감지값 갱신 
// MoveState.cs의 DoChecks() 발췌
public override void DoChecks()
{
    base.DoChecks();

    isPlayerInMinAgroRange = entity.CheckPlayerInMinAgroRange();
    isDetectingLedge = entity.CheckLedge();
    isDetectingWall = entity.CheckWall();
    isGrounded = entity.CheckGround();
    isCheckJump = entity.CheckJump();
}

곰의 이동 상태는 다음 if / else if 순서로 조건을 평가합니다. 한 번의 판단에서 먼저 성립한 분기를 선택하며, 마지막 분기는 이동 상태를 유지한 채 진행 방향과 속도를 바꿉니다.

순서확인하는 상황수행하는 동작
1플레이어가 최소 감지 범위 안에 있음플레이어 감지 상태로 전환
2점프가 필요한 지형을 감지함점프 상태로 전환
3정해진 이동 시간이 지남대기 상태로 전환
4지상에서 벽 또는 절벽을 감지함방향을 뒤집고 이동 속도를 다시 적용
코드 보기: Bear_MoveState.cs - 상태 전환 우선순위 
// Bear_MoveState.cs의 LogicUpdate() 발췌
public override void LogicUpdate()
{
    base.LogicUpdate();
    if (isPlayerInMinAgroRange)
    {
        stateMachine.ChangeState(bear.playerDetectedState);
    }
    else if (isCheckJump)
    {
        stateMachine.ChangeState(bear.jumpState);
    }
    else if (isMoveTimeOver)      // idle 시간이 끝나면
    {
        stateMachine.ChangeState(bear.idleState);      // move상태로 돌입
    }
    else if ((isDetectingWall || !isDetectingLedge) && isGrounded)
    {
        entity.Flip();
        entity.SetVelocity(stateData.movementSpeed);    // 방향 재설정
    }

}

2.4 상태 데이터와 애니메이션 이벤트 연결

행동 로직과 조정값 분리

이동 상태는 D_MoveState라는 ScriptableObject로 이동 속도와 최소·최대 이동 시간을 전달받습니다. MoveState.Enter()는 이 설정으로 속도를 적용하고 이동 시간을 뽑으며, LogicUpdate()가 startTime을 기준으로 만료 여부를 계산합니다. 같은 이동 로직을 여러 몬스터가 상속하면서 설정 에셋을 다르게 지정할 수 있습니다.

코드 보기: D_MoveState.cs - 이동 상태 설정

애니메이션 타이밍을 상태 동작으로 전달

돌진 상태는 진입 즉시 돌진을 끝내는 대신, 애니메이션 이벤트가 실제 동작 시작·종료 시점을 알려 주도록 연결합니다.

  1. Dash.Enter()가 현재 돌진 상태를 AnimationToStateMachine.dashState에 연결하고, 완료·수행 플래그를 초기화합니다.
  2. 애니메이션의 TriggerDashing() 이벤트가 전달되면 DashState가 수행 플래그를 켜고 돌진 속도를 적용합니다. 곰의 상태는 여기에 물리 저항값을 추가합니다.
  3. FinishDashing() 이벤트는 완료 플래그를 켜고 수행 플래그와 속도를 정리합니다.
  4. 다음 논리 업데이트에서 Bear_DashState가 완료·수행 플래그를 확인하고, 플레이어 감지 여부에 따라 감지 또는 탐색 상태로 전환합니다.

using System.Collections;

먼저 공통 행동 상태를 상속해 몬스터별 전환 조건을 작성하고, 필요한 상태 데이터 에셋을 지정합니다. 그다음 몬스터의 초기화 코드에서 상태 객체를 생성하고 시작 상태를 Init()에 전달합니다. 공격·돌진처럼 애니메이션 시점에 맞춰 실행할 동작은 이벤트 전달 클래스에 현재 상태를 연결합니다. 이렇게 공통 생명주기와 센서 처리는 재사용하고, 몬스터별 조건·설정·이벤트 연결을 확장합니다.

3. 플레이어 슬라임 및 변신 시스템

플레이어 슬라임의 움직임, 공격, 대시, 피격 처리를 구현했습니다. 컴포지션 패턴을 활용하여 각 기능을 독립적인 클래스로 분리하고, Player_Slime에서 통합 관리합니다. 기능 클래스는 Player_State를 거쳐 공통 State 생명주기를 상속하며, 실행 시점은 플레이어 컨트롤러가 결정합니다.

3.2 변신 능력 시스템

플레이어가 몬스터를 처치하면 해당 몬스터의 형태로 변신할 수 있습니다. 변신 시 각 형태의 고유 능력을 사용할 수 있으며, Player_FormMovement를 통해 특수 이동 로직이 활성화됩니다.

  • 슬라임 (기본): 원거리 포물선 공격, 대시 무적 프레임 활용.
  • 토끼 (변신): 더블 점프 및 벽 점프 능력 획득. Rabbit_ability와 연동하여 벽 점프 중 조작 제한 물리 로직 적용.

// Player_Slime.cs에서 필드와 Start()를 발췌
public class Player_Slime : Player_Entity
{
    public Player_SlimeMovement movement { get; private set; }
    public Player_Attack attack { get; private set; }
    public Player_Dash dash { get; private set; }
    public Player_Dead dead { get; private set; }

    [SerializeField] private D_PlayerMovement movementData;
    [SerializeField] private D_PlayerAttack attackData;
    [SerializeField] private D_PlayerDash dashData;
    [SerializeField] private D_PlayerDead deadData;
    [SerializeField] private Transform meleePos;

    [SerializeField] private Player_HpBar hpBar;

    private SpriteRenderer formSpriteRenderer;

    protected override void Start()
    {
        base.Start();
        formSpriteRenderer = GetComponent<SpriteRenderer>();

        facingDirection = 1;
        sensor = new Player_Sensor(this, sensorData, ForwardSensorPos, MiddleSensorPos, BackwardSensorPos);
        movement = new Player_SlimeMovement(this, movementData, this);
        attack = new Player_Attack(this, attackData, meleePos);
        dash = new Player_Dash(this, dashData);
        dead = new Player_Dead(this, deadData);
    }
}
