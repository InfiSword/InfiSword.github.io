1. 객체 구성과 화면 처리

1.1 기능을 조합하는 GameObject

플레이어, 몬스터, 자원 오브젝트는 GameObject를 바탕으로 필요한 기능을 조합합니다. 위치는 Transform, 이미지는 SpriteRenderer, 충돌은 Collider, 동작 재생은 Animator가 담당합니다. 공통 기능을 분리해 객체마다 같은 코드를 반복하지 않고 재사용할 수 있도록 구성했습니다.

클래스역할
GameObject컴포넌트를 소유하고 객체의 갱신·렌더링을 연결
ObjectManager객체 생성·삭제와 공간 그리드 조회
CameraManager카메라에 보이는 월드 범위를 계산해 렌더링 대상 조회
RenderManager그리기 요청을 레이어와 깊이 순서로 정렬해 출력
코드 보기: 컴포넌트 추가와 조회

AddComponent는 기능을 생성해 unique_ptr로 소유하고, 호출한 객체에는 접근용 포인터를 반환합니다. GetComponent는 요청한 타입의 기능을 찾습니다.

template <typename T, typename... Args>
T* AddComponent(Args&&... args) {
    auto newComponent = std::make_unique<T>(this, std::forward<Args>(args)...);
    T* componentPtr = newComponent.get();
    m_components.push_back(std::move(newComponent));
    return componentPtr;
}

template <typename T>
T* GetComponent() const {
    for (const auto& component : m_components) {
        if (!component) continue;
        T* target = dynamic_cast<T*>(component.get());
        if (target) return target;
    }
    return nullptr;
}

1.2 필요한 객체만 골라 순서대로 그리기

그리드는 셀마다 std::vector<GameObject*>를 갖는 2차원 배열로 관리합니다. 셀 크기는 월드 좌표 기준 256이며, m_spatialGrid[x][y]에는 해당 칸에 속한 객체의 포인터를 보관합니다. 객체는 중심 위치에 해당하는 셀에 등록하고, 이동해 셀이 바뀌면 기존 셀에서 제거한 뒤 새 셀에 넣습니다.

화면에 보이는 객체를 찾을 때는 카메라의 월드 영역을 셀 좌표 범위로 바꾸고, 그 범위의 셀만 순회합니다. 비활성·삭제 예정 객체를 제외하고, 각 객체의 사각형이 화면 영역과 실제로 겹치는지(AABB) 검사해 렌더링 대상에 담습니다.

  1. 화면 범위 계산카메라 위치로 월드 좌표의 가시 영역 계산
  2. 가시 객체 조회그리드 후보 조회 후 사각형 겹침 검사
  3. 그리기 요청 수집스프라이트와 위치·레이어·깊이를 전달
  4. 정렬 후 출력레이어별 깊이 순서로 GDI+에 그리기

SpriteRenderer는 화면에 그릴 정보를 만들고, RenderManager는 이를 모아 출력합니다. 객체마다 즉시 그리는 방식에서 순서 관리를 분리해, 타일·월드 객체·UI의 겹침을 일관되게 처리합니다.

셀별 객체 목록 — ObjectManager

배열의 두 인덱스는 셀의 X·Y 좌표이며, 각 vector가 그 셀의 객체 목록입니다. 배열 크기는 맵 크기와 셀 크기로 정합니다.

그리드 자료구조

static constexpr int GRID_CELL_SIZE = 256;
static constexpr int GRID_WIDTH = (MAP_WIDTH * TILE_SIZE / GRID_CELL_SIZE) + 2;
static constexpr int GRID_HEIGHT = (MAP_HEIGHT * TILE_SIZE / GRID_CELL_SIZE) + 2;

std::vector<GameObject*> m_spatialGrid[GRID_WIDTH][GRID_HEIGHT];

화면과 겹치는 객체 찾기 — QueryObjectsInRectArea

화면에 걸친 셀 순회 → 활성 객체 확인 → 화면과 겹치면 결과에 추가하는 흐름입니다. startX~endX, startY~endY는 카메라 영역에 해당하는 셀 범위이며, rectArea는 카메라가 보는 월드 사각형입니다.

뷰어 조작법

파란 점선의 카메라 영역을 마우스나 손가락으로 드래그해 이동합니다. 키보드는 Tab으로 카메라 영역을 선택한 뒤 방향키로 이동하며, 리셋 버튼 또는 Home 키로 초기 상태로 돌아갑니다.

카메라 X: 1244, Y: 726
활성 셀 12 / 30
렌더링 14
제외 28
제외 비율 67%

아래는 조회 흐름을 간단히 표현한 예시입니다. 원본의 사각형 비교식은 두 영역의 겹침을 확인하는 GDI+의 IntersectsWith로 표현했습니다.

코드 보기: 화면 영역 조회 
for (int y = startY; y <= endY; ++y) {
    for (int x = startX; x <= endX; ++x) {
        for (auto* obj : m_spatialGrid[x][y]) {
            if (!obj->IsEnabled() || obj->IsDead()) continue;

            if (rectArea.IntersectsWith(obj->GetBounds())) {
                targetOutObjects.push_back(obj);
            }
        }
    }
}

결과 목록인 targetOutObjects를 렌더링에 사용합니다. 실제 구현에서는 셀 범위를 맵 경계 안으로 제한하고, 조회 번호로 같은 객체의 중복 검사도 방지합니다.

CameraManager — 화면에 보이는 객체의 렌더링 요청

QueryObjectsInRectArea가 그리드 조회와 최종 겹침 검사를 수행하고, 결과를 재사용 버퍼에 담습니다.

std::vector<GameObject*>& visibleBuffer = m_queryBuffer;

objectManager->QueryObjectsInRectArea(GetViewportWorldRect(), visibleBuffer);

RenderManager::Flush — 레이어별 정렬과 출력

같은 레이어에서는 zOrder가 작은 요청부터 그립니다. ExecuteDrawCommand가 요청 종류에 따라 이미지·텍스트 등을 GDI+로 출력하고, 사용한 목록은 비웁니다.

for (int i = LAYER_TILE_BACKGROUND; i < LAYER_COUNT; ++i) {
    if (m_layerCommands[i].empty()) continue;

    std::stable_sort(m_layerCommands[i].begin(), m_layerCommands[i].end(),
        [](const DrawCommand& a, const DrawCommand& b) {
            if (a.zOrder != b.zOrder) return a.zOrder < b.zOrder;
            return a.layer < b.layer;
        });

    for (const auto& cmd : m_layerCommands[i]) {
        ExecuteDrawCommand(pGraphics, cmd);
    }
    m_layerCommands[i].clear();
}

2. 애니메이션과 행동 연결

2.1 이미지에서 동작으로

스프라이트 시트를 프레임으로 나누고, 상태와 방향에 맞는 동작을 재생합니다. SpriteSheet가 이미지 영역을 분리하고, AnimationClip이 프레임과 재생 시간을 보관합니다. Animator는 경과 시간에 맞춰 표시할 스프라이트를 SpriteRenderer에 전달합니다.

예를 들어 Pig의 아래 방향 대기는 4열 시트의 33개 프레임을 등록해 반복 재생합니다. 다른 상태도 같은 구조에서 이미지와 재생 설정을 바꿔 사용합니다.

2.2 동작의 타격 시점에 게임 로직 실행

도끼질은 애니메이션 재생과 실제 나무 타격이 같은 시점에 일어나야 합니다. 이를 위해 특정 프레임에 이름 있는 이벤트를 등록하고 콜백으로 행동을 연결했습니다. chop_hit에서는 효과음과 타격 처리를, chop_end에서는 행동 종료를 실행합니다.

동작 선택 → 재생 시간 갱신 → 이벤트 프레임 확인 → 타격·종료 콜백 실행 순서입니다. 한 번의 갱신에서 여러 프레임을 지나쳐도 그 사이의 이벤트를 확인하도록 구성했습니다.

코드 보기: 도끼질 프레임과 타격 이벤트 연결

플레이어의 CHOP 클립에 타격 프레임 4와 종료 프레임 35를 등록합니다. Animator가 해당 프레임을 지나갈 때 등록된 콜백을 호출합니다.

const int CHOP_HIT_FRAME = 4;
const int CHOP_LAST_FRAME = 35;
AnimationClip* clip = m_animator->GetAnimationClip((int)PlayerState::CHOP, (Direction)dir);
if (clip) {
    clip->AddEventFrame(CHOP_HIT_FRAME, L"chop_hit");
    clip->AddEventFrame(CHOP_LAST_FRAME, L"chop_end");
    clip->SetEventCallback([this](int frameIndex, const std::wstring& eventName) {
        if (eventName == L"chop_hit") {
            SoundManager::GetInstance()->PlaySFX(L"Resource/Sound/PlayerSound/Chop_tree.wav");
            this->OnChopHit();
        }
        else if (eventName == L"chop_end") {
            this->OnChopEnd();
        }
    });
}

3. 에디터와 데이터 반영

3.1 오브젝트의 기준점과 충돌 영역 편집

자체 제작한 ObjectEditor에서 이미지를 보며 피벗(배치 기준점)과 박스·원형 콜라이더를 조정합니다. 저장한 값은 object_resource_overrides.txt에서 객체 ID별로 관리합니다. 게임 시작 시 DataManager가 기본 리소스 설정에 이 값을 덮어써, 설정 변경을 클라이언트 재컴파일 없이 반영합니다.

코드 보기: ID별 피벗과 콜라이더 설정 반영

설정 파일을 읽어 기존 리소스 ID를 찾고, 해당 ID의 피벗과 충돌 영역을 갱신합니다. 각 객체는 초기화할 때 이 설정을 조회해 사용합니다.

ResourcePathUtils::ParseObjectResourceOverridesFile(
    L"GameData/object_resource_overrides.txt",
    [this](GameObjectID id, const ResourcePathUtils::ObjectResourceDef& overrideDef) {
        auto it = m_objectResources.find(id);
        if (it != m_objectResources.end()) {
            it->second.pivotX = overrideDef.pivotX;
            it->second.pivotY = overrideDef.pivotY;
            it->second.hasCollider = overrideDef.hasCollider;
            it->second.colliderType = overrideDef.colliderType;
            it->second.colliderOffsetX = overrideDef.colliderOffsetX;
            it->second.colliderOffsetY = overrideDef.colliderOffsetY;
            it->second.colliderWidth = overrideDef.colliderWidth;
            it->second.colliderHeight = overrideDef.colliderHeight;
            it->second.colliderCenterX = overrideDef.colliderCenterX;
            it->second.colliderCenterY = overrideDef.colliderCenterY;
            it->second.colliderRadius = overrideDef.colliderRadius;
        }
    });

3.2 맵 배치에서 게임 월드 생성까지

MapEditor는 .dsm 파일에 맵 크기, 시작 위치, 타일, 객체, 이동 가능 영역을 구간별로 저장합니다. 클라이언트는 파일을 읽어 맵 데이터를 구성하고, 오브젝트의 ID와 좌표로 실제 게임 객체를 생성합니다. 배치 정보와 오브젝트별 설정을 분리해, 같은 종류의 객체가 공통 설정을 사용하도록 했습니다.

  1. 배치·설정 편집타일·객체·시작 위치와 피벗·충돌 영역 조정
  2. 파일 저장맵은 .dsm, 객체 설정은 별도 텍스트로 저장
  3. 클라이언트 로드객체 설정을 갱신하고 맵의 섹션별 데이터를 해석
  4. 게임 객체 생성ID·좌표로 객체를 만들고 초기화 시 공통 설정 사용
코드 보기: 맵의 ID·좌표 읽기와 객체 생성

맵 해석 — ParseMapFileInto

.dsm의 OBJECTS 구간에서 읽은 ID와 좌표를 MapData에 담습니다. 타일과 플레이어 시작 위치도 각각의 구간에서 읽습니다.

GameObjectID objID = EnumTables::GetGameObjectID(id.c_str());
if (objID != GOID_NONE) {
    float objX = std::stof(x);
    float objY = std::stof(y);

    ResourcePathUtils::ObjectResourceDef objData;
    objData.id = objID;
    objData.x = objX;
    objData.y = objY;
    outMapData.gameObjects.push_back(objData);
}

월드 생성 — GameScene::CreateGameObjectsFromMapData

저장된 객체를 순회하며 다음 호출로 생성합니다. 객체의 종류는 ID로 결정하고, 위치는 맵에서 읽은 값을 사용합니다.

objectManager->CreateObject(id, objData.x, objData.y);
