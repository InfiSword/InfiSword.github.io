1. CSV 데이터 파이프라인

기획 데이터는 여러 Google 스프레드시트로 나뉘어 있습니다. 파일별 갱신 여부 판단과 C# 객체 변환을 공통화해, 각 테이블에서 같은 다운로드·변환 코드를 반복하지 않도록 구성했습니다. CSV는 시트의 행과 열을 텍스트로 내보낸 형식입니다.

  1. 메타 시트 확인데이터 종류·버전·다운로드 주소 조회
  2. 버전 비교일치하면 캐시, 다르면 다운로드
  3. CSV 변환열 이름을 C# 필드에 연결하고 타입 변환
  4. 인게임 조회변환된 데이터를 ID로 등록·조회

1.1 필요한 파일만 갱신

메타 시트는 각 데이터 파일의 종류·버전·주소를 모은 목록입니다. 이 목록의 버전과 PC에 저장된 CSV를 비교해 같은 버전이면 로컬 캐시를 읽고, 다르거나 파일이 없으면 다운로드합니다. 캐시를 읽지 못한 경우도 다운로드 대상으로 돌립니다.

마스터 시트와 CSV 주소 관리 구조

마스터 시트의 Link 주소 목록을 따라 각 CSV를 다운로드합니다. 받은 CSV는 C# 데이터 객체로 변환해, 몬스터·스킬 등 게임에서 사용하는 데이터로 등록합니다.

1.2 CSV를 C# 데이터로 변환

리플렉션으로 실행 중인 C# 클래스의 필드 목록을 읽어 CSV 열과 연결합니다. 열 이름과 필드 이름의 표기를 맞춘 뒤, 값을 int·float·string으로 변환해 객체에 넣습니다.

FieldInfo[] fields는 필드 정보 객체를 모은 배열입니다. FieldInfo의 자세한 설명은 Microsoft 공식 문서: FieldInfo를 참고해 주세요.

예를 들어 아래 시트의 Name 열은 별칭 규칙을 거쳐 Data_Monster.m_monsterName에 연결됩니다. 몬스터 이름 한 칸이 C# 객체의 문자열 필드로 들어가는 흐름입니다.

FieldInfo를 채택한 이유

  • 사용 이유: 몬스터·스킬처럼 서로 다른 데이터 클래스를 하나의 CSV 파서로 처리하기 위해, 실행 중 클래스의 필드를 찾는 방식을 선택했습니다.
  • 장점: 테이블마다 값을 옮기는 코드를 반복하지 않고, 공통 이름 매핑과 타입 변환을 재사용할 수 있습니다.
  • 주의점: 직접 대입보다 필드 조회·값 설정 비용이 추가되고, 열 이름·타입 불일치를 컴파일 단계에서 알기 어렵습니다. 필드나 별칭을 추가할 때 매핑·변환 결과를 확인해야 합니다.

2. Seed·Token으로 난수 상태 저장·복원

Seed는 난수 생성의 시작값입니다. 같은 생성 방법과 시드에서 같은 순서로 난수를 요청하면 같은 순서의 숫자를 얻습니다. 시드만 저장하면 처음부터 다시 뽑으므로, 몇 번 사용했는지 함께 기록해 저장한 뒤 필요한 값부터 이어 쓰도록 설계했습니다.

  1. 시드 분리기능마다 따로 난수 생성기 준비
  2. 사용량 기록기능마다 난수를 뽑은 횟수 기록
  3. 토큰 저장시드와 사용 횟수를 문자열로 저장
  4. 난수 이어 쓰기사용한 만큼 다시 뽑아 버리고 이어 쓰기

2.1 도메인별 난수 분리

Domain : uint Enum의 ID로 구별하며, Map = 1·Quest = 4처럼 기능마다 관련 도메인 ID(정수값)와 해당 ID의 사용량을 따로 관리합니다.

RNG는 난수 생성기, 도메인은 맵·대화·스킬처럼 난수를 사용하는 기능 구분입니다.

도메인별 관리 자료구조

두 사전 모두 Domain Enum을 키로 사용합니다. _domainRng는 ID별 난수 생성기, _domainUsageCounts는 ID별 사용량(ulong)을 보관합니다.

static readonly Dictionary<Domain, System.Random> _domainRng =
    new Dictionary<Domain, System.Random>();

static readonly Dictionary<Domain, ulong> _domainUsageCounts =
    new Dictionary<Domain, ulong>();

시드 파생: 기본 시드가 +1이나 -1만큼 달라도 그 차이가 여러 비트에 퍼지도록, SplitMix64에서 영감을 받은 믹싱으로 기본 시드와 도메인 ID를 섞습니다. 아래 코드로 int 서브 시드를 만들고, 이를 받은 System.Random이 실제 게임 난수를 생성합니다.

코드 보기: DeriveSubSeed 
static int DeriveSubSeed(long baseSeed, uint salt)
{
    unchecked
    {
        ulong z = (ulong)baseSeed + 0x9E3779B97F4A7C15UL + ((ulong)salt * 0x85EBCA6BUL);
        z = (z ^ (z >> 30)) * 0xBF58476D1CE4E5B9UL;
        z = (z ^ (z >> 27)) * 0x94D049BB133111EBUL;
        z = z ^ (z >> 31);
        return (int)(z & 0x7FFFFFFF); // 하위 31비트를 int 서브 시드로 사용
    }
}

도메인 초기화와 난수 사용량 기록

아래 코드는 초기화 함수 Init과 난수 요청 함수 NextInt입니다. Init은 DeriveSubSeed를 호출해 기본 시드와 도메인 ID를 SplitMix64 유사 믹싱으로 섞고, 그 결과인 서브 시드로 도메인별 System.Random을 초기화합니다. 실제 난수는 이 생성기에서 얻습니다.

int 자료형 난수가 필요하면 NextInt에 도메인과 범위를 전달합니다. 호출할 때마다 해당 도메인의 사용량을 기록하고, 지정한 범위의 난수를 반환합니다.

1. Init — 도메인별 난수 생성기와 사용량 초기화

코드 보기: Init 
public static void Init(long seed)
{
    BaseSeed = seed;
    _domainRng.Clear();
    _domainUsageCounts.Clear();
    foreach (Domain d in Enum.GetValues(typeof(Domain)))
    {
        _domainRng[d] = new System.Random(DeriveSubSeed(seed, (uint)d));
        _domainUsageCounts[d] = 0UL;
    }
    IsInitialized = true;
}

2. NextInt — 해당 도메인의 사용량 기록과 난수 반환

코드 보기: NextInt 
public static int NextInt(Domain domain, int minInclusive, int maxExclusive)
{
    _domainUsageCounts[domain] = _domainUsageCounts.GetValueOrDefault(domain, 0UL) + 1UL;
    return _domainRng[domain].Next(minInclusive, maxExclusive);
}

2.2 토큰 저장과 난수 이어 쓰기

토큰 저장 규격

아래 상수는 자료형의 크기가 아니라 토큰 안의 십진수 저장 자릿수입니다. 저장·해석에 같은 폭을 사용합니다.

const int BASE_SEED_WIDTH = 20;    // ulong 최대값 기준 20자리
const int COUNT_WIDTH = 3;         // 도메인 개수 3자리
const int DOMAIN_ID_WIDTH = 3;     // 도메인 ID 3자리
const int USAGE_WIDTH = 12;        // 사용량 12자리

현재 게임의 토큰 문자열 길이: 총 233자리(도메인 14개 기준)

시드 20자리와 도메인 수 3자리에, 도메인마다 ID 3자리·사용량 12자리를 붙입니다. 도메인 하나는 15자리이고, 14개는 210자리이므로 20 + 3 + 14 × (3 + 12) = 233자리입니다. 사용하지 않은 도메인도 사용량을 0으로 채워 포함합니다.

1. 토큰 생성 — BuildSeedToken

BuildSeedToken은 기본 시드와 도메인별 사용 횟수를 받아, 저장용 숫자 문자열인 Token을 만듭니다. long 시드는 unchecked((ulong)baseSeed)로 비트 패턴을 보존해 저장합니다.

Pad는 숫자를 문자열로 바꾸고, 정해진 자릿수보다 짧으면 앞을 0으로 채웁니다. 덕분에 구분자가 없어도 저장할 때와 같은 자릿수로 잘라 읽을 수 있습니다.

저장 순서: 시드 20자리 → 도메인 수 3자리 → [ID 3자리 + 사용량 12자리] 반복

예시: 시드 42 · Map 3회 · Quest 5회 (나머지 12개 도메인은 0회)
저장된 구간해석
00000000000000000042시드 42
014도메인 14개
001 | 000000000003Map: 3회
004 | 000000000005Quest: 5회

|는 난수 ID와 해당 ID의 난수 사용량을 구분하기 위한 표시입니다. 실제 토큰은 인게임 도메인 ID순으로 14개의 데이터를 다루며, 시드 → 도메인 수 → [도메인 ID → 난수 사용량] 순서로 구분자 없는 하나의 문자열로 저장합니다.

도메인 ID순으로 정렬한 domains를 돌며 사용량 사전에서 횟수를 읽고, 기록이 없으면 0을 넣습니다. 생성된 난수 목록 대신 시작값과 진행 횟수를 저장하는 방식입니다.

코드 보기: BuildSeedToken · Pad

Pad — 숫자를 정해진 자릿수의 문자열로 저장

Pad는 숫자를 문자열로 바꾸고, width보다 짧으면 앞을 0으로 채웁니다. 예를 들어 Pad(42UL, 20)은 "00000000000000000042"를 만듭니다. uint 버전은 도메인 수·ID를, ulong 버전은 시드·사용 횟수를 처리합니다.

ulong encodedSeed = unchecked((ulong)baseSeed);
string token = Pad(encodedSeed, BASE_SEED_WIDTH);
token += Pad((uint)domains.Count, COUNT_WIDTH);
foreach (GameSeed.Domain d in domains)
{
    ulong count = usage != null ? usage.GetValueOrDefault(d, 0UL) : 0UL;
    token += Pad((uint)d, DOMAIN_ID_WIDTH);
    token += Pad(count, USAGE_WIDTH);
}
return token;

// 저장할 숫자의 자릿수 맞추기
static string Pad(uint value, int width) => value.ToString().PadLeft(width, '0');
static string Pad(ulong value, int width) => value.ToString().PadLeft(width, '0');

2. 토큰 해석 — RestoreUsageCount

토큰 문자열을 기본 시드와 [도메인 → 사용 횟수] 사전으로 되돌립니다. 먼저 시드와 도메인 수를 읽고, 시드는 저장할 때의 변환을 반대로 적용해 원래의 long 값으로 복구합니다.

ReadUInt는 현재 위치 idx에서 정해진 글자 수 width만큼 잘라 숫자로 바꿉니다. 읽은 만큼 idx를 옮기고, ref idx로 다음에 읽을 위치도 함께 바꿔 이어 읽습니다.

위 저장 예시인 시드 42·도메인 14개를 읽으면 다음과 같습니다.

읽는 구간반환값·다음 위치
시드 20자리
00000000000000000042		반환값 42
idx:0→20
도메인 수 3자리
014		반환값 14
idx:20→23

이후 idx = 23부터 ID 3자리·사용량 12자리를 14번 읽습니다. 숫자 ID를 Domain Enum으로 바꾸고, 해당 사용 횟수를 사전에 연결합니다. 이렇게 읽은 시드와 사전을 RestoreRNG에 전달하면 난수 상태 복구가 시작됩니다.

코드 보기: RestoreUsageCount · ReadUInt

ReadUInt — 토큰의 한 구간을 숫자로 읽고 다음 구간으로 이동

토큰 s에서 현재 위치 idx부터 width글자를 잘라 숫자로 반환합니다. ref idx로 읽은 길이만큼 호출한 쪽의 위치도 옮기므로, 다음 호출은 바로 다음 구간을 읽습니다.

앞의 저장 예시에서 시드 20자리를 읽으면 42를 반환하고 idx는 0 → 20, 이어 도메인 수 3자리를 읽으면 14를 반환하고 idx는 20 → 23이 됩니다.

int idx = 0;
ulong baseSeedEncoded = ReadUInt(token, ref idx, BASE_SEED_WIDTH);
long baseSeed = unchecked((long)baseSeedEncoded);
uint count = (uint)ReadUInt(token, ref idx, COUNT_WIDTH);
Dictionary<GameSeed.Domain, ulong> usage = new Dictionary<GameSeed.Domain, ulong>();
for (int i = 0; i < count; i++)
{
    uint domIdU = (uint)ReadUInt(token, ref idx, DOMAIN_ID_WIDTH);
    ulong u = ReadUInt(token, ref idx, USAGE_WIDTH);
    usage[(GameSeed.Domain)domIdU] = u;
}
GameSeed.RestoreRNG(baseSeed, usage);

// 한 구간을 읽고 다음 위치로 이동
static ulong ReadUInt(string s, ref int idx, int width)
{
    string slice = s.Substring(idx, width); // 읽을 구간 추출
    idx += width; // 호출한 쪽의 위치도 갱신
    return ulong.Parse(slice); // 문자열 → 숫자
}

3. 난수 상태 복구 — RestoreRNG

RestoreRNG는 해석한 시드와 사용량 사전을 받아, 도메인별 난수 생성기의 진행 위치를 되찾습니다. 각 도메인 ID와 기본 시드를 DeriveSubSeed로 섞어 같은 생성기를 다시 만들면, 난수는 처음부터 나옵니다.

따라서 저장된 사용 횟수만큼 난수를 다시 뽑아 버린 뒤, 다음 요청부터 저장 당시의 다음 값을 반환하도록 합니다. 사용량 카운터도 같은 횟수로 맞춰, 이후 저장할 때 누적 사용량이 이어지게 합니다.

사용량을 저장해야 하는 이유: 설명용으로 Map의 난수 순서가 12 → 47 → 8 → 31이라고 가정합니다. 앞의 세 값을 사용한 뒤 저장했다면, 이어서 필요한 값은 31입니다.

저장한 정보불러온 뒤 다음 값
시드만 저장12 — 처음부터 다시 시작
시드 + Map 사용량 331 — 이미 쓴 앞의 세 값을 건너뛴 뒤 사용
코드 보기: RestoreRNG 
foreach (KeyValuePair<Domain, ulong> kv in usageCounts)
{
    Domain d = kv.Key;
    ulong count = kv.Value;     // 토큰 사용량
    System.Random rng = _domainRng[d] = new System.Random(DeriveSubSeed(baseSeed, (uint)d));
    for (ulong i = 0; i < count; i++)
    {
        rng.Next();     // 사용한 횟수만큼 숫자를 버림 호출하여 RNG 상태를 맞춤
    }
    _domainRng[d] = rng;
    _domainUsageCounts[d] = count;   // 사용량 상태 업데이트
}

게임 데이터와 난수 생성 방법이 같아야 같은 결과를 이어 쓸 수 있습니다. 체력·위치는 따로 저장해야 하며, 사용 횟수가 많을수록 다시 뽑아 버리는 작업도 늘어납니다.
