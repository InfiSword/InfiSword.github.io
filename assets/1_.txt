Don’t Starve 모작을 개발하면서 AI를 활용해 전용 에디터를 만들었습니다. 
개발을 진행하면서 맵에 오브젝트를 배치하거나 콜라이더 충돌 영역을 검사하는 코드와 수치를 매번 직접 실행해 확인하는 일이 번거로웠으며, 화면에서 직접 결과를 볼 수 있는 도구가 필요하다고 생각했습니다.
먼저 맵을 구성하는 작업, 그리고 오브젝트의 콜라이더나 피벗값 같은 정보를 수정하는 작업이 필요했습니다. 그래서 이를 중심으로 에디터를 2개의 씬으로 분할하고, 해당 내용을 저장하고 불러오는 과정까지 설계하고자 했습니다.
이제 이 작업을 맡기기 위해서 먼저 맵을 불러오고, 그 맵을 화면에 직접 그리기 위해서 클라이언트 쪽에 씬 클래스와 렌더링 관련 클래스를 넘겨주고, 오브젝트의 정보를 수정해야 하니 피벗, 콜라이더 등의 오브젝트 관련 클래스를 AI에게 분석하게 하고, 이를 문서화하여 실제 코드를 생성하는 작업을 할 때는 배치, 오브젝트 편집, 저장과 불러오기 등 기능별로 각 클래스를 나누어 단일 책임 원칙을 준수하도록 요청했습니다. 받은 코드는 기존 클라이언트 함수와 연결되는 부분을 살핀 뒤 데이터를 적용되도록 설계했고, 실행 결과가 의도와 다르면 어떤 부분이 내가 원하던 기능 부분이나 클래스 설계 부분과 달랐는지 설명하고, 수정 요청 후에는 같은 조작을 반복해 문제가 해결됐는지 확인했습니다.
이 과정에서 에디터를 조작해 저장한 값이 클라이언트 쪽에서도 에디터와 게임이 데이터 파일을 같은 규칙으로 읽도록, 맵과 오브젝트 설정 모두 에디터와 게임이 공통 파서를 사용하도록 클라이언트와 에디터 함수를 연결해 사용했습니다. 
이렇게 클라이언트에서 데이터를 파싱하는 과정과 에디터로 데이터를 저장하는 로직을 완성하고 에디터를 이용해 게임에 해당 데이터를 반영할 수 있게 됐습니다. AI는 구현 적용과 반복적인 코드 수정을 진행했고, 저는 수정 요구사항과 코드 설계 및 정보를 문서화하고, 이를 바탕으로 코드 통합과 동작 검증을 맡았습니다.
