# Feature Specification: WinAPI Don't Starve 핵심 흐름 정리

**Feature Branch**: `main` (기존 작업 유지, 커밋 금지)
**Created**: 2026-10-20
**Status**: Ready
**Input**: 핵심 기능과 처리 흐름 위주로 간결하게 정리하고 기존 이미지와 접기·펼치기 핵심 코드를 활용한다.

## User Scenarios & Testing

### User Story 1 - 핵심 구현 파악 (Priority: P1)
면접관이 객체 구성, 화면 처리, 행동 이벤트, 에디터 데이터의 연결을 짧은 설명으로 이해한다.
**Why this priority**: 긴 세부 구현보다 설계 의도와 책임 구분을 먼저 전달한다.
**Independent Test**: 코드를 펼치지 않아도 각 기능의 입력·처리·결과를 설명할 수 있다.
**Acceptance Scenarios**:
1. Given 보고서, When 본문을 읽으면, Then 세 장에서 기능과 처리 흐름을 확인한다.
2. Given 기존 이미지, When 해당 절을 읽으면, Then 설명에 맞는 이미지와 캡션을 함께 본다.

### User Story 2 - 필요할 때 코드 확인 (Priority: P2)
독자가 실제 C++ 구현의 핵심만 선택해 확인한다.
**Independent Test**: 모든 코드가 기본 접힘이며 클릭·탭·Enter·Space로 열고 닫힌다.
**Acceptance Scenarios**:
1. Given 접힌 코드, When summary를 작동하면, Then 해당 기능의 코드와 짧은 안내가 표시된다.

### User Story 3 - 기존 탐색 보존 (Priority: P2)
기존 갤러리와 원본 이미지 열람을 데스크톱과 모바일에서 사용한다.
**Independent Test**: 갤러리 8장, 썸네일과 이전·다음 버튼이 작동하고 페이지 가로 넘침이 없다.

### Edge Cases
- 긴 C++ 행은 코드 영역 안에서 스크롤하며 문서 전체를 밀어내지 않는다.
- 이미지 로딩 전에도 크기를 확보하고 원본 링크를 유지한다.
- 현재 C++ 소스와 과거 글이 다르면 현재 코드의 동작을 따른다.

## Requirements
### Functional Requirements
- **FR-001**: 본문은 객체·렌더링, 애니메이션·이벤트, 에디터·데이터의 세 장으로 정리한다.
- **FR-002**: 원본 갤러리와 메타데이터를 보존한다.
- **FR-003**: 기존 Pig 스프라이트와 에디터 이미지를 기능 설명에 활용한다.
- **FR-004**: 핵심 코드는 네이티브 details/summary로 기본 접힘 상태로 제공한다.
- **FR-005**: 설명과 코드는 실제 프로젝트에서 확인된 역할과 호출 관계를 따른다. 성능 수치를 새로 주장하지 않는다.
- **FR-006**: 기존 디자인, 다른 페이지의 미커밋 수정, 게임 소스를 보존한다. 커밋·푸시·배포하지 않는다.
### Key Entities
- 보고서 절: 목적, 처리 흐름, 코드, 시각 자료.
- 코드 영역: 기능 이름, 설명, C++ 핵심 구현, 접힘 상태.

## Success Criteria
### Measurable Outcomes
- **SC-001**: 본문 세 장과 7개 코드 접기 영역으로 핵심 구현을 확인한다.
- **SC-002**: 데스크톱·Pixel 5에서 7개 영역의 포인터·Enter·Space 조작이 모두 통과한다.
- **SC-003**: 375/768/1024/1440px에서 문서 가로 넘침이 없고 모든 사용 이미지가 정상 로드된다.
- **SC-004**: 빌드, 기존 74개 테스트, 갤러리 회귀 검증이 통과한다.

## Assumptions
- 대상 독자는 게임 클라이언트 개발 면접관이며 기존 포트폴리오 표현을 유지한다.
- 로컬 임시 빌드에만 반영한다.

## Follow-up: 1.2 그리드 조회 설명
- 256 크기 셀과 셀별 vector<GameObject*>를 갖는 2차원 배열을 설명한다.
- 중심 위치 기반 등록, 화면의 셀 범위 계산·경계 제한·활성 객체 AABB 검사 순서를 짧게 설명한다.
- ds-grid-query 코드 접기를 기존 렌더링 코드 앞에 추가한다. 실제 선언과 조회 로직 사용.
- 기존 레이아웃·갤러리·이미지·게임 소스 보존, 커밋 금지. 코드 접기는 총 6개.

## Follow-up: QueryObjectsInRectArea 가독성
- 겹치는 셀 순회·활성 객체 필터·화면 겹침 검사·결과 추가만 보이는 짧은 C++ 예시로 정리한다.
- GDI+ IntersectsWith로 비교식을 표현했음을 밝히고 원본 게임 코드는 수정하지 않는다. 기존 접기는 유지한다.

## Follow-up: 셀 좌표 계산 예시
- 기존 11줄 조회 코드는 유지한다. 내림/올림 후 1 빼기 규칙과 숫자 예시를 접기 내부 설명에 추가한다.
- 셀 크기 256, 카메라 영역 (300,100)~(768,512) 예시에서 X=1~2, Y=0~1, 총 4개 셀임을 설명한다. 커밋 금지.

## Follow-up: 그리드 그림과 설명 공개
- 카메라 (300,100)~(768,512)와 검사 대상 4개 셀을 서로 다른 색·테두리로 표시하는 단순 SVG 그림을 추가한다.
- 해당 그리드 설명·계산 예시·그림을 details 밖으로 옮겨 항상 표시한다. 자료구조/조회 코드는 별도 details 안에 코드만 둔다. 총 7개 코드 접기. 커밋 금지.

## Follow-up: 그리드 내 객체의 최종 겹침 검사
- 기존 4개 검사 셀과 카메라 그림에 예시 객체 4개를 추가한다. 2개는 카메라 안에서 렌더링, 2개는 검사 셀 안이지만 카메라 밖이어서 제외된다.
- 결과는 색과 모양(원·체크 / 사각형·X) 및 범례·캡션·대체 설명으로 구분한다. 코드·접기 구조 유지, 커밋 금지.

## Follow-up: 이전 그리드 뷰어 재사용
- 이전 원문에 있던 카메라 드래그·객체 색상·HUD·리셋 기능의 6×5 그리드 뷰어를 정적 그림 대신 복원한다. 기존 설명과 코드 전용 접기 7개는 보존한다.
- 위의 4개 셀 계산은 별도 수치 예시이며 뷰어 수치는 움직임에 따라 바뀜을 짧게 표시한다. 커밋 금지.

## Follow-up: 초기 활성 셀 12개와 한글 설명
- 고정 4셀 예시를 제거하고 초기 뷰어의 X 인덱스 1~4, Y 1~3 및 (4-1+1)×(3-1+1)=12 계산으로 대체한다. 그림의 1부터 시작하는 번호와 배열 인덱스 대응을 명시한다.
- 셀 단위 경계 1.57~4.43, 1.26~3.68은 뷰어 격자의 시작점·셀 크기로 환산한 값임을 명시해 HUD 좌표와 혼동하지 않도록 한다.
- 세 객체 설명을 각 한글 제목과 한 문장으로 줄이고 뷰어의 영문 표기도 핵심 한글로 정리한다. 동작·코드 접기·커밋 금지 유지.

## Follow-up: 셀 단위 경계값의 출처
- 뷰어 내부 좌표의 격자 시작점 (30,75), 카메라 경계 (260,195)~(680,425), 격자 880×475/6열×5행을 설명한다.
- (경계−격자 시작점)/셀 크기의 네 계산과 내림/올림 후1빼기를 한 줄씩 연결한다. 기존12개 결과와 조회11줄·커밋금지 유지.

## Follow-up: 핵심 범위와 뷰어 사용 안내
- 세부좌표·소수·내림/올림 계산을 제거하고 초기4열×3행=12개셀과 후보선별→화면겹침검사만 남긴다.
- 뷰어 밖에 마우스/터치·Tab+방향키·리셋/Home 조작법 및 셀강조/점선/객체색/상단수치 의미를 짧게 추가한다. 기존뷰어·코드 유지, 커밋금지.

## Follow-up: 상시 표시 안내 박스와 큰 범례
- 뷰어 조작법·표시 의미를 하나의 항상 보이는 박스로 감싼다.
- SVG 하단 세 객체 설명의 제목과 본문을 키우고 기존 문구·동작은 유지한다.
- 초기검사범위 제목과12개 설명 문단은 제거한다. 커밋금지.

## Follow-up: 표시 의미 삭제와 뷰어 글자 확대
- 안내 박스에서 표시 의미 제목/목록을 삭제하고 조작법은 그대로 둔다.
- 뷰어의 수치·셀번호·태그·콜아웃·하단범례를 모두 확대한다. 배지/설명 간격도 조정해 글자 잘림과 겹침을 방지한다. 커밋 금지.
# 후속 요청: 그리드 자료구조 상시 표시
- `ds-grid-storage`의 접기를 제거하고 기존 선언 코드를 항상 표시한다. 나머지 코드 접기와 내용은 유지하며 커밋하지 않는다.

## 후속 요청: 맵 저장 항목 명시
- 에디터 설명에 .dsm의 구간별 저장 항목 다섯 가지만 명시한다. 추가 기능 설명과 커밋은 하지 않는다.
